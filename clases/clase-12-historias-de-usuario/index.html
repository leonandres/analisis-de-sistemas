Fundamento Ágil

1. Concepto y Filosofía Ágil

Representación breve de un requerimiento desde la perspectiva del usuario final.

Una Historia de Usuario (HU) es una descripción corta, clara y sencilla de una necesidad del usuario expresada en su propio lenguaje. A diferencia de las especificaciones tradicionales pesadas, la historia de usuario busca ser una "invitación a la conversación" entre el equipo de desarrollo y el Product Owner.

📋 Requerimiento Tradicional

"El sistema deberá permitir la consulta de saldo mediante el protocolo HTTPS enviando un token JWT..."

✨ Historia de Usuario (Ágil)

"Como cliente bancario quiero consultar mi saldo desde el móvil para saber si me alcanza antes de pagar."

Estructura Estándar

2. El Formato Canónico y las 3 C

Estructura sintáctica y modelo de Card, Conversation, Confirmation por Ron Jeffries.

COMO [Rol de Usuario]
QUIERO [Acción / Funcionalidad]
PARA [Beneficio de Negocio / Valor]
🗂️ 1. Card (Tarjeta)

Resumen físico o digital de la intención funcional.

💬 2. Conversation

Diálogo constante entre PO, analista y desarrolladores.

✅ 3. Confirmation

Criterios de aceptación para validar su cumplimiento.

Calidad de Requisitos

3. Criterios de Calidad INVEST

Principios creados por Bill Wake para evaluar la madurez de una Historia de Usuario.

I - Independent

Independiente de otras historias para facilitar la priorización.

N - Negotiable

Negociable entre PO y equipo; no es un contrato cerrado.

V - Valuable

Debe aportar un valor concreto para el usuario o negocio.

E - Estimable

El equipo debe poder estimar su tamaño o esfuerzo.

S - Small

Pequeña para ser completada en un único Sprint.

T - Testable

Verificable mediante pruebas claras de aceptación.

BDD & Escenarios

4. Criterios de Aceptación (Given - When - Then)

Especificación mediante ejemplos orientados al comportamiento (BDD/Gherkin).

Escenario 1: Pago exitoso con tarjeta de crédito
DADO que el cliente tiene una tarjeta válida con saldo suficiente
CUANDO hace clic en "Confirmar Compra"
ENTONCES el sistema emite el comprobante y envía un correo de confirmación.
Métricas Ágiles

5. Estimación mediante Story Points

Planning Poker y escala de Fibonacci (1, 2, 3, 5, 8, 13, 21).

Los Story Points representan una medida relativa que combina complejidad, riesgo y esfuerzo. No equivalen a horas hombre absolutas, sino al tamaño relativo de la tarea comparada con una historia base de referencia.
