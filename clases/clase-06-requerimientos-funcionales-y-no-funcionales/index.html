1. Fundamentos y metodología

Definiciones base y comportamiento en las etapas del ciclo de vida.

El enfoque del usuario

Requerimiento

Es una necesidad o solicitud cuyo objetivo primordial es resolver un problema o cumplir una meta del usuario.

El enfoque del sistema

Requisito

Es una condición o capacidad técnica necesaria que debe poseer el sistema para satisfacer las necesidades del usuario (Requerimientos del Sistema).

¿Dónde los encontramos en la metodología?

Relevamiento / Reconocimiento Se relevan, capturan, escuchan, observan, detectan y documentan las necesidades del usuario (requerimientos del usuario).
Análisis de requisitos Se definirán los Requerimientos (requerimientos del sistema) indispensables para cumplir con el usuario.
Gestión del proyecto Se administrarán los requerimientos, incorporando los cambios de manera controlada para cumplir los plazos.

2. Tipos de requerimientos

División fundamental de las expectativas y restricciones del software.

Requerimientos funcionales (Qué hace)

Describen las funcionalidades, servicios o transformaciones que el sistema realiza sobre las entradas para producir salidas. Representan el comportamiento específico del software.

Ejemplos de la cátedra:
  • El sistema debe asignar alumnos en los cursos.
  • El sistema debe controlar la superposición de horarios.
  • El sistema debe generar el comprobante de inscripción.

Requerimientos no funcionales (Cómo debe ser)

Son los atributos, propiedades emergentes o características que definen el cómo el sistema realizará el trabajo. Actúan como restricciones planteadas al sistema respecto a cómo se implementan las funciones.

📂 De Producto o Calidad:

Definición: Restricciones impuestas directamente al comportamiento dinámico y operativo del sistema en ejecución. Especifican atributos medibles de rendimiento, usabilidad, confiabilidad o seguridad.

Ejemplo: Ante un fallo, el sistema no deberá tardar más de 5 minutos en restaurar los datos, o procesar respuestas en menos de 2 segundos.

📂 Organizacionales:

Definición: Limitaciones operacionales derivadas directamente de las políticas internas, estándares del proceso o infraestructura tecnológica preexistente en la organización del cliente o desarrollador.

Ejemplo: Obligación de utilizar una Base de Datos Oracle, implementar Interfaz Web o programar bajo un lenguaje específico.

📂 Externos:

Definición: Restricciones impuestas por factores totalmente exógenos ajenos al sistema y a la propia empresa de desarrollo, tales como marcos regulatorios, legislaciones estatales o reglamentos institucionales.

Ejemplo: Cumplir de forma estricta con los reglamentos internos de la Facultad, normativas fiscales o leyes de protección de datos personales.
